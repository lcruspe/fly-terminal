# Fly Terminal updater

`Tools → Обновить Fly Terminal` обслуживается `tools/update_stack.py`.

## Порядок обновления

1. `git fetch origin main`;
2. проверка локальных изменений отслеживаемых файлов;
3. автоматическая очистка только заведомо генерируемых macOS-артефактов (`.DS_Store`);
4. проверка трёхстороннего объединения локальных настроек `macos/Caddyfile` и `macos/gateway/admin.html`, если эти файлы изменены в обновлении;
5. сохранение таких настроек в именованную резервную копию `git stash`, `git pull --ff-only origin main` и восстановление настроек;
6. перезапуск LaunchAgents Fly Terminal;
7. проверка готовности сервисных портов.

Пользовательские изменения исходников никогда не сбрасываются автоматически. Локальные настройки автоматически совмещаются с обновлением, если Git может объединить их без конфликта. Резервная копия остаётся в `git stash list`; её идентификатор записывается в журнал. При конфликте или staged-изменениях настроек обновление останавливается до изменения файлов и перечисляет конкретный путь. Остальные локальные изменения сохраняются обычным `git pull --ff-only`, который отказывает при пересечении с обновлением. При ошибке pull настройки восстанавливаются; перезапуск не выполняется. Статус сохраняет конкретный шаг ошибки.

## `.DS_Store`

`.DS_Store` запрещён в репозитории через `.gitignore` и удалён из `main`. Это важно для macOS-инсталляции: Finder может менять такой файл независимо от Fly Terminal, и ранее это ошибочно блокировало preflight обновления как локальное изменение проекта.

Для старых checkout, где `.DS_Store` ещё отслеживается старой версией Git и старый updater уже заблокирован, требуется однократное восстановление файла из текущего локального HEAD перед первым pull. После получения актуального `main` повторяться это не должно.
