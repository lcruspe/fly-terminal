# RoomAudio — публичный маршрут и плитка Fly Terminal

## Назначение

RoomAudio хранит записи с Windows Mate, предоставляет веб-архив и live-прослушивание, локальную расшифровку речи на Mac mini. Сервис обслуживается отдельным Python-процессом на Mac; **Fly Terminal не реализует собственную аудиозапись**.

## Доступ и архитектура

- Внешний вход: `https://129-158-49-130.sslip.io/roomaudio/` (HTTPS на Oracle).
- Oracle пересылает основной HTTPS gateway по SSH reverse tunnel на Caddy Mac mini (локальный порт 8080).
- `macos/Caddyfile` обслуживает `/roomaudio` → `/roomaudio/` и проксирует `/roomaudio/*` через `handle_path` на `{$FLY_ROOMAUDIO_UPSTREAM:http://127.0.0.1:8766}`. Префикс удаляется перед обращением к RoomAudio.
- Приложение RoomAudio само аутентифицирует запросы; gateway **не должен перехватывать** его `Authorization` собственной Basic Auth. Cookies сессии привязаны к `/roomaudio` и имеют `Secure; HttpOnly; SameSite=Lax`.
- Маршруты `/roomaudio/ingest/*`, `/roomaudio/client/*` и `/roomaudio/setup/*` заблокированы на публичном gateway с ответом 404. Они предназначены только для частного подключения источника. Не удалять это ограничение при синхронизации окружений.
- Отсутствие авторизации на `/roomaudio/api/status` должно давать 401; `/roomaudio/` выдаёт страницу входа (HTTP 200).
- Стартовая страница `macos/gateway/admin.html` содержит самостоятельную плитку **RoomAudio** с относительной ссылкой `/roomaudio/`, атрибутом `data-health="roomaudio"`; клиентский индикатор проверяет доступность при загрузке.

## Где что находится

- Основной Fly Terminal: `macos/Caddyfile`, `macos/gateway/admin.html`, `macos/gateway/gateway.js`.
- Отдельное приложение на Mac: `~/Library/Application Support/RoomAudio/` (`server.py`, `index.html`, `transcriber.py`, архивные API, конфигурация).
- Аудиоархив и модели — на внешнем диске WD в `/Volumes/WD/RoomAudio/`.
- Конфигурация RoomAudio содержит пароль и ключ ingest; **не коммитить её, аудиофайлы, БД и логи**.
- Автозапуск RoomAudio реализован через пользовательский `launchd`.
- Изменения в `macos/Caddyfile` могут быть локально расширены окружением (например, индивидуальными upstream-маршрутами). Синхронизация проекта должна сохранять локальные deployment overrides.

## Проверки публикации

```sh
curl -k -o /dev/null -w '%{http_code}\n' https://129-158-49-130.sslip.io/roomaudio/              # 200 (логин)
curl -k -o /dev/null -w '%{http_code}\n' https://129-158-49-130.sslip.io/roomaudio/api/status    # 401 без авторизации
curl -k -o /dev/null -w '%{http_code}\n' https://129-158-49-130.sslip.io/roomaudio/ingest/check # 404
```

Все три кода проверены 12.10.2026.

## Диагностика

Если `/roomaudio/` отдаёт 502, проверять по цепочке: `RoomAudio :8766` → `Caddy :8080` → `SSH reverse tunnel` → `Oracle HTTPS`. Если вход доступен, но проигрыватель не получает медиа, проверить сессии и media token самого RoomAudio до изменения прокси. Если нет плитки, убедиться, что Caddy отдаёт актуальную `admin.html` из `{$FLY_TERMINAL_REPO_ROOT}/macos/gateway`.

## Интерфейс прослушивания (24.10.2026)

- **Эфир** — раздел по умолчанию. Один источник Mate с состоянием соединения, последней связью и явной кнопкой «Слушать». Автовоспроизведение не применяется. До запуска потока стандартный аудиоплеер скрыт; «Остановить» прекращает запрос и проигрывание.
- **Архив** — единый рабочий экран: выбор периода (не более суток), поиск по тексту **всего периода**, сгруппированные сеансы и связанный текст. При выборе сеанса отображается его текст, при выборе фрагмента — фразы этого фрагмента; поиск по периоду временно заменяет текущую выборку. Кнопка «Весь период» восстанавливает полный текст.
- Архивный плеер появляется только после попытки прослушивания; содержит перемотку, скорость и переход к следующей речи. При смене разделов текущий звук останавливается, отложенные запросы не должны запускать невидимый плеер. Экспорт MP3, TXT, SRT и копирование текста объединены в одном меню и действуют на **весь выбранный период** (не только результаты поиска).
- Спектрограмма, 15-секундные фрагменты, временная шкала, статистика и управление очисткой находятся в «Подробностях аудио» и «Очистке и управлении архивом». Режим записи — в «Настройках источника»; изменение запрошенного режима не трактуется как подтверждение со стороны Mate.
- Статус недоступного источника содержит объяснение, последнюю связь и команду восстановления. Успех восстановления требует нового потока, а не только ответа на POST. Резервный HLS строится по архивным фрагментам и **не является** полноценным непрерывным эфиром.
- `roomaudio/macos/index.html` — исходный HTML/JS/CSS без этапа сборки; развёрнутая копия — `~/Library/Application Support/RoomAudio/index.html`. Перед публикацией синхронизировать оба файла и проверить их идентичность. Другие deployment overrides (включая `macos/Caddyfile`) при обновлении UI не трогать.

### Регрессионные проверки UI

В тестах нет реальных паролей, разговоров или аудиофайлов. Playwright подменяет ответы API тестовыми фразами; проверки не запускают микрофон, очистку или восстановление Mate.

```sh
# Playwright и Chromium должны быть установлены в указанном окружении Python
python3 -m unittest roomaudio.macos.tests.test_ui_smoke -v
python3 -m unittest discover -s roomaudio/macos/tests -p 'test_*.py' -v
```

Проверять как минимум: стартовый эфир, недоступный источник и кнопку восстановления, архив и привязку текста к выбранному сеансу, поиск по всему периоду, управление шкалой с клавиатуры, скрытие/остановку плеера при смене раздела, мобильную ширину без горизонтальной прокрутки. Настоящее воспроизведение и получение звука требуют отдельной проверки со включённым Mate: фиктивные медиаответы Playwright этого не подтверждают.


### Восстановление источника, когда Mate недоступен (24.10.2026)

- `/api/recovery` **не будит и не включает ноутбук**. Обработчик после авторизованного POST с корректным `Origin` лишь сохраняет `recovery_id` в `capture_settings.json` и сбрасывает live-буфер. Команда выполняется **только когда запущенный** на Windows `capture_manager.py` снова опросит `/client/recording-mode` и подтвердит `recovery_ack`.
- Отличать три состояния: **команда сохранена** (POST 200 и идентификатор) → **Mate подтвердил перезапуск захвата** (`recovery_ack` совпал, запрошенный режим применён) → **поступают свежие аудиоданные** (`/api/live/status: online`). Ни одно из первых двух не доказывает возможность слушать. Режим `off` намеренно оставляет микрофон выключенным.
- UI теперь не считает временную ошибку последующих GET-запросов провалом уже принятого POST. Очередь отображается без бессмысленного 60-секундного ожидания. Проверка состояния выполняется существующими периодическими запросами страницы. Ответы 401/403 на отправку команды показываются отдельно; при недоступном эфире действие «Слушать» блокируется.
- `client_last_seen` хранится в памяти сервера и сбрасывается при его перезапуске, поэтому отсутствие значения **не означает**, что ноутбук никогда не был подключён. Сообщение в UI учитывает этот факт.
- Диагностика физически недоступного Mate: убедиться, что ноутбук включён, имеет доступ к сети и запущены три процесса (`capture_manager.py`, `uploader.py`, `AudioMonitor/autostart.py`). На самом Mate для идемпотентного восстановления предусмотрен `roomaudio/windows/Ensure-RoomAudio.ps1`, который не меняет режим записи и не создаёт дубликаты работающих процессов. После появления `client_connected` проверить `recovery_ack`, затем `online`; проверять реально полученный звук только после действия пользователя «Слушать».
- Регрессионные тесты: `roomaudio/macos/tests/test_ui_smoke.py` имитирует принятие команды в очередь при недоступном Mate и ошибку отправки 403; проверяет, что статусы не смешиваются. Эти тесты не заменяют реальную проверку включённого устройства.
