# Tools

Раздел **Tools** — сервисные действия Fly Terminal, которые выполняются через `session-control.py` и штатные скрипты из `tools/`.

## Текущие инструменты

- **Подписка и локация Happ** — выбор подписки, затем одной из локаций этой подписки; список читается через Accessibility из установленного Happ Plus.
- **Переподключить Happ** — штатное отключение и повторное подключение VPN через `scutil --nc`.
- **Восстановить стек Chromium** — восстановление Colima/Docker, browser-контейнера, LaunchAgents и проверка HTTP/WebSocket-доступности.
- **Обновить Fly Terminal** — `git fetch` + `git pull --ff-only`, перезапуск системных служб и ожидание готовности портов.
- **Обмен файлами** — единый интерфейс с двумя направлениями: загрузка файлов **на виртуальную машину** и выбор файла **на виртуальной машине** для скачивания на локальный компьютер.

## Компоновка интерфейса Tools

Пользовательский интерфейс Tools организован по задачам, а не по внутренним компонентам реализации:

1. **VPN** — подписка, локация, текущая активная связка и действие переподключения находятся в одном блоке. Отдельный блок `VPN Happ` не используется.
2. **Обмен файлами** — общий экран Documents сервера, очереди загрузки с клиента и скачивания. Выбор или перетаскивание сразу запускает передачу; поиск фильтрует серверные файлы. Кнопка Downloads открывает папку сохранения Chromium.
3. **Система** — восстановление Chromium и обновление Fly Terminal собраны в отдельном административном блоке.

Статусные строки файлового обмена по умолчанию пусты и используются только для текущей операции, результата или ошибки. Файловый браузер при каждом открытии начинает навигацию с `/config/Downloads`, поскольку это папка сохранения загрузок Chromium; переход выше по дереву остаётся доступным кнопкой `↑`.

## Контракт ошибок Tools

Пользовательский интерфейс не должен показывать технические идентификаторы ошибок, stderr команд, traceback, `exit N`, названия внутренних шагов или сырые сообщения `scutil`, Docker, Git и `launchctl`.

Control API разделяет ошибку на два уровня:

- `error` — стабильный машинный код для логики приложения, например `happ_connect_timeout`;
- `message`, `details`, `summary` — человекочитаемое сообщение на русском языке, пригодное для прямого вывода в Tools;
- `technicalDetails` — исходная низкоуровневая диагностика, если она была получена. Она предназначена для диагностики и не должна выводиться пользователю;
- для статусов восстановления/обновления исходный текст неуспешного шага сохраняется как `technicalMessage`, а `message` нормализуется перед выдачей через API.

Центральная таблица кодов ошибок находится в `TOOL_ERROR_MESSAGES` в `session-control.py`. Ошибки фоновых операций нормализуются функциями `operation_failure_message()` и `humanize_operation_status()`.

### Правило для новых инструментов

При добавлении нового действия в Tools:

1. Backend возвращает стабильный `error`-код, а не технический текст в качестве идентификатора ошибки.
2. Для каждого пользовательски достижимого `error`-кода добавляется человекочитаемое сообщение в `TOOL_ERROR_MESSAGES`.
3. Низкоуровневый stderr/exception при необходимости сохраняется только как техническая диагностика.
4. Если действие выполняется фоновым скриптом и пишет status JSON, неуспешные шаги должны нормализоваться перед выдачей через `/api/.../status`.
5. Frontend показывает `message` / `details` / `summary` и не должен выводить `error`, `technicalDetails` или `technicalMessage` как пользовательский текст.

## Нормализованные сценарии

### Happ

Человекочитаемые сообщения предусмотрены для следующих ситуаций:

- служба Happ недоступна;
- переподключение уже выполняется;
- не удалось отключить VPN;
- превышено время ожидания отключения;
- не удалось запустить VPN;
- превышено время ожидания подключения;
- выбранная локация отсутствует;
- другая операция Happ уже выполняется;
- не удалось переключить локацию.

### Подписки и локации Happ

В разделе **VPN** используются существующие подписки и серверы установленного **Happ Plus**. `GET /api/vpn/happ/subscriptions` возвращает два зависимых списка (подписка → локации) и текущий выбор. Совместимый alias: `GET /api/vpn/happ/locations`. `POST /api/vpn/happ/location` принимает `subscriptionId` и `locationId`. Входные идентификаторы проверяются по заново прочитанному каталогу.

**Источник истины — интерфейс Happ через системный Accessibility API macOS**, а не его приватный CFNetwork-кэш. Компилируемый по необходимости `macos/happ-ax.swift` читает имена подписок, имена серверов и их AX-идентификаторы; для выбора сервера вызывает штатное действие `AXPress` («Выбрать сервер»). Поддерживаются кириллические наименования. Пароли, URL подписок, токены, конфигурации и содержимое зашифрованного хранилища Happ не считываются и не возвращаются по API.

Текущий сервер сверяется с `connectedConfigJson` только **на чтение**, если Accessibility не возвращает признак выделения. При сравнении учитываются флаги стран в `remarks`, которые иногда отсутствуют в подписи AX-строки; совпадение принимается только тогда, когда оно однозначно во всех подписках. Завершение операции подтверждается повторным чтением текущего выбранного сервера. Нет записи в `XRAY_CURRENT*`, нет прямого изменения настроек Happ и нет управления routing deeplink: эти действия выполняет сам Happ при штатном выборе.

Кнопка **Обновить список** повторно читает актуальные серверы из интерфейса Happ. Обновление серверов у провайдера выполняется самим Happ, а не через CFNetwork-кэш Fly-terminal.

**Требования:** установленный и запущенный Happ, разблокированная графическая сессия macOS с доступным главным окном и разрешение Accessibility для процесса, запускающего мост. При блокировке экрана macOS скрывает Accessibility-дерево окна Happ; backend возвращает отдельную ошибку `happ_screen_locked`, а не имитирует успешное переключение. В случае отсутствия прав, окна или доступных серверов API сообщает об ошибке вместо фиктивного успеха. Исполняемый Swift-мост собирается в `~/Library/Caches/FlyTerminal/`; параллельные сборки не используют общий временный файл.

Смена VPN может кратковременно разорвать соединение браузера с Mac mini; клиенту следует повторно прочитать каталог и сверить фактический текущий сервер. Отдельная кнопка **Переподключить** по-прежнему использует `scutil --nc` для активной конфигурации без смены локации.

Существующие функции чтения CFNetwork-кэша и старого маппинга UUID оставлены только для обратной совместимости внутренних тестов и не используются публичными маршрутами выбора серверов. При дальнейшей очистке их можно удалить отдельно с соответствующими тестами.

### Восстановление Chromium

Ошибки группируются по пользовательскому смыслу, а не по конкретной shell-команде: Docker/Colima, запуск Chromium, LaunchAgents, готовность портов, HTTP/WebSocket-проверки и общая фатальная ошибка.

### Обновление Fly Terminal

Отдельные сообщения предусмотрены для проверки локальных изменений, `git fetch`, `git pull --ff-only`, перезапуска системных служб и ожидания готовности сервисных портов.

## Диагностика

Технические детали не теряются: исходные status-файлы и `.log` фоновых операций остаются источником низкоуровневой диагностики. API нормализует их только в представлении, которое получает UI Tools.


## Файлы Documents

Файловый обмен реализован как штатный инструмент раздела **Tools** и обслуживается `session-control.py`. Канонический каталог задаётся `FLY_TERMINAL_DOCUMENTS_DIR` и по умолчанию равен `~/Documents` пользователя macOS; текущий каталог tmux-сессии для этой функции не используется. Каждый новый upload сразу копируется в постоянный каталог Chromium `/config/Documents`, а `launch-browser.sh` синхронизирует туда доступные существующие файлы при запуске. Копирование вместо macOS bind-mount не даёт зависшему VirtioFS остановить запуск browser-контейнера. Файлы macOS с флагом `dataless` сначала должны быть загружены из iCloud.

### API

- `GET /api/files/list` — список обычных файлов верхнего уровня `Documents` с именем, размером и временем изменения, а также текущим лимитом загрузки `maxUploadBytes`.
- `POST /api/files/upload` — загрузка произвольного файла. Тело JSON содержит `fileName`, `mimeType` и base64-поле `data`. Максимальный размер самого файла задаётся существующей переменной `FLY_TERMINAL_MAX_UPLOAD_BYTES` (по умолчанию 25 МБ).
- `GET /api/files/download?name=...` — потоковое скачивание файла. Ответ содержит определённый по расширению `Content-Type`, `Content-Length` и `Content-Disposition` с `filename*` в UTF-8.

### Безопасность путей и совпадения имён

API принимает только одно имя файла без компонентов пути. `/`, `\\`, управляющие символы, `.`/`..` и чрезмерно длинные имена отклоняются. Список не показывает символические ссылки. При скачивании файл открывается относительно дескриптора каталога `Documents` с запретом перехода по финальной символической ссылке (`O_NOFOLLOW`), после чего `fstat()` подтверждает, что открыт обычный файл. Это исключает подмену файла на symlink между проверкой и открытием.

Загрузка резервирует файл атомарно через создание с `O_EXCL`, поэтому существующий файл никогда не перезаписывается молча. При совпадении имени создаётся вариант `имя (2).ext`, затем `имя (3).ext` и т. д.; API сообщает UI поле `renamed`.

Пользовательские ошибки файлового инструмента проходят через общий `TOOL_ERROR_MESSAGES`; низкоуровневая диагностика сохраняется в `technicalDetails` и не выводится в интерфейсе.


## Скачивание файлов из Chromium-контейнера

В **Tools → Обмен файлами → На локальный компьютер** кнопка **«Выбрать файл на виртуальной машине»** открывает серверный файловый браузер Chromium-контейнера (`FLY_BROWSER_CONTAINER_NAME`, по умолчанию `fly-terminal-browser`). Навигация начинается с `/config/Downloads`: пользователь вручную переходит по каталогам; кнопка `↑` позволяет подняться вплоть до `/` и нажимает **«Скачать»** у нужного обычного файла. Ответ `Content-Disposition: attachment` формируется внешним Fly Terminal, поэтому файл скачивается браузером на локальный компьютер пользователя; промежуточное копирование в `~/Documents` не требуется.

### API файлового браузера контейнера

- `GET /api/container/files/list?path=/...` — перечисляет обычные каталоги и файлы выбранного каталога. Каталоги идут первыми; для файлов возвращаются размер и время изменения. Максимальное число элементов задаётся `FLY_TERMINAL_CONTAINER_FILE_MAX_ENTRIES` (по умолчанию 2000).
- `GET /api/container/files/download?path=/...` — потоково передаёт один выбранный файл из Chromium-контейнера в локальный браузер. Backend запускает внутри контейнера Python-процесс, открывает файл с `O_NOFOLLOW`, проверяет через `fstat()`, что это обычный файл, сначала передаёт его метаданные, а затем тот же открытый файловый дескриптор стримится в HTTP-ответ. Это исключает TOCTOU-подмену финального файла между проверкой и чтением.

### Ограничения и безопасность

Пути принимаются только абсолютные и нормализуются как POSIX-пути. Файловый браузер не показывает символические ссылки и не разрешает переход через symlink-компоненты. Виртуальные системные деревья `/proc`, `/sys`, `/dev` и `/run` исключены: они содержат устройства и псевдофайлы, чтение которых может зависать или иметь побочные эффекты. Остальная обычная файловая система контейнера доступна для ручной навигации в пределах прав контейнера. Ошибки Docker, доступа и чтения преобразуются в человекочитаемые сообщения через общий `TOOL_ERROR_MESSAGES`.


### Общий экран обмена

Tools → Файлы показывает Documents сервера и очередь передачи одновременно. Выбор файлов или перетаскивание запускает последовательную загрузку; у каждого файла есть прогресс и отмена. Ошибка одного файла не останавливает очередь. Поиск фильтрует список файлов сервера. Файловый браузер Chromium открывает `/config/Downloads`, с прямыми переходами в Downloads и Documents.

`POST /api/files/upload` также принимает бинарное тело `application/octet-stream`, `Content-Length` и заголовок `X-File-Name` с percent-encoded UTF-8 именем. Сервер пишет блоками по 1 МБ, проверяет лимит до чтения, удаляет файл при обрыве передачи и сохраняет защиту от перезаписи. JSON/base64 остаётся совместимым с прежними клиентами. Прогресс 100% означает отправку тела; подтверждение сохранения показывается после ответа сервера.


### Удаление файлов

Documents сервера и папки `/config/Downloads`, `/config/Documents` Chromium поддерживают удаление одного файла и очистку всех обычных файлов верхнего уровня. UI запрашивает подтверждение; поиск не ограничивает очистку. Подпапки и символические ссылки сохраняются. Удаление действует на выбранную папку; копии в других папках остаются.

`POST /api/files/delete` принимает `{ "name": "file.txt" }` или `{ "all": true }`. `POST /api/container/files/delete` дополнительно требует `directory`, равный `/config/Downloads` или `/config/Documents`. Ответ содержит `deleted` и `failed`, чтобы частичное удаление было видно пользователю. Во время загрузки UI блокирует удаление из Documents.
